## 1. 安全修复（重点）

| 项 | 说明 | 证据 |
| --- | --- | --- |
| 课程问题可见性 | 课程问题**仅课程成员 / 作者 / 管理员**可见，未加入者返回 `QA-3006`；公开问题对所有访问者可见 | `QuestionQueryService.requireCanView`（`5e11953`）、`docs/reports/v1-scope-decisions-2026-11-25.md` 决策 1 |
| 公开问题管理权 | `canManageCourse(userId, null)` 不再对任意全局 TEACHER 放行——公开问题仅作者与 ADMIN 可管理 | `820a5e1`、`IdentityApiImplPermissionTest` |
| 课程成员名单 | `GET /api/v1/courses/*/members` 由匿名可读改为**仅登录可读** | `820a5e1`、`SecurityConfig` |
| 限流原子性 | 登录失败计数改为 Lua 原子 `INCR`+`PEXPIRE`，进程中断不再产生无 TTL 的永久锁定 key；损坏计数降级为未锁定并自愈 | `RedisLoginThrottle`（#222、#238） |
| 限流配置生效 | 修正配置键 `co.security.login-max-failures` → `co.security.login.max-failures`（原键与 yml 不匹配，恒用默认 5）；非法值启动即失败 | #238 |
| 角色变更会话失效 | `changeRole` 后立即撤销该用户全部会话，旧 ADMIN 权限不再保留至会话过期 | `AdminUserService`（#238） |
| 生产部署 | 修复 Cookie `Secure` 与 HTTP 部署冲突；后端 8080 不再直出 host，只经 Nginx 同源代理 | `a018918`、README §5 |
| 敏感配置 | 生产 compose 的密钥/密码必须由 `deploy/.env` 注入（`CO_FIELD_KEY`/`CO_FIELD_MAC_KEY`/`DB_PASSWORD` 等），无默认值 | README §5 |

## 2. 一致性与并发修复

- **Q&A**：投票并发与计数、缓存代际（缺失时禁用缓存避免回读旧 gen0）、作者删除改为数据库原子条件、删除已采纳回答时释放 `acceptedAnswerId`、详情对历史脏数据 `accepted_answer_id` 容错、浏览量批次落库失败不丢数据（`384b244`/`10982bd`/`6779a3a`/`4880066`/`c6ab251`/`f281d76`）
- **Reputation**：每题仅一个 OPEN 悬赏由数据库唯一约束兜底；公开问题不允许发起悬赏（`REP-1007`）；悬赏 404 与到期退款、结算可见性（`58391ba`/`594fea5`/`66b7171`）；投票日上限改为**账户行锁内重算**（#238）
- **Discovery**：相关问题对未授权/已删除问题的校验补齐（`66b7171`）

## 4. 部署步骤（按 README §5，生产口径）

```bash
# 1) 准备密钥（无默认值，必须显式提供）
cp deploy/.env.example deploy/.env
#    填写 DB_PASSWORD / MYSQL_ROOT_PASSWORD / CO_FIELD_KEY / CO_FIELD_MAC_KEY / GRAFANA_PASSWORD

# 2) 一键启动（生产 compose）
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build

# 3) 可选：加监控（Prometheus + Grafana）
docker compose --env-file deploy/.env -f deploy/docker-compose.yml --profile observability up -d --build
```

**本地开发/演示**（含 demo 数据）：

```bash
docker compose -f deploy/docker-compose.dev.yml up -d --build
```

**访问地址**：

| 服务 | 生产 compose | dev compose |
| --- | --- | --- |
| 前端 | <http://localhost/> | <http://localhost/> |
| 后端 API | <http://localhost/api/>（Nginx 同源代理，8080 不暴露） | <http://localhost:8080/> |
| 健康检查 | <http://localhost/actuator/health> | <http://localhost:8080/actuator/health> |

## 5. 升级说明（从 v1.0.0）

- **无需数据库迁移**：修复均为应用层逻辑与配置，Flyway 版本未变；
- **配置项变化**：登录限流键名统一为 `co.security.login.*`（若曾在 `deploy/.env` 或环境变量覆盖旧键 `CO_SECURITY_LOGIN_MAX_FAILURES`，请同步为新键名）；
- **行为变化**（预期）：
  1. 未加入课程的学生打开课程问题会看到「没有查看权限」；
  2. 全局教师不能再编辑/删除他人的公开问题；
  3. 匿名访问课程成员名单返回 401；
  4. 角色变更后该用户需重新登录。
