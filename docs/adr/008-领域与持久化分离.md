# ADR-008：领域对象与 JPA 实体分离

**状态**：已接受 ｜ **驱动特征**：可测试性、可演进性 ｜ **相关场景**：FF-1
**修订**：2026-11-19 按实现复核补「后果 · 实现注记」三条（版本号不由适配器搬运 / 计数器两种落地 / 计数器的只读快照约定）——刘俊琒

## 背景
若领域聚合直接标注 `@Entity`，领域模型就被 JPA 的要求（无参构造、可变字段、延迟加载代理）绑架，
单元测试也需要启动持久化上下文；而课程的核心目标之一就是让学生体会“领域模型是纯粹的业务模型”。

## 决策
领域层是纯 Java（零框架依赖），仓储**接口**定义在领域层；基础设施层提供 `*JpaEntity` 与 `*RepositoryAdapter` 完成映射。
计数器类字段（分数、回答数、浏览数）不由聚合回写，而由原子 `UPDATE` 维护，避免“读-改-写”覆盖并发增量
（即时原子 SQL 与缓冲批量累加两种形态见「后果 · 实现注记 2」）。

## 后果
- 正面：领域测试毫秒级、无容器；更换持久化技术只影响适配器；聚合边界与事务边界更清晰。
- 负面：存在映射样板代码（约每个聚合 40 行）；乐观锁的版本号交由实体 `@Version` 负责，适配器**不回写**（见下方实现注记 1）。

### 实现注记（2026-11-19 复核后回写）

本节是决策落地后按代码逐行复核补上的，目的是让后来者**不必按文档去找不存在的代码**。三处与初版表述的差异：

1. **版本号不做"搬运"，冲突在边界统一翻译。**
   `toDomain` 会读 `e.getVersion()` 进领域对象，但 `save` **从不回写**；乐观锁完全由 JPA 实体的 `@Version` 承担。
   代价是领域层感知不到并发冲突：冲突以 `ObjectOptimisticLockingFailureException` 在适配器层抛出，
   再由 `GlobalExceptionHandler.optimisticLock` 统一译成 `409 / SYS-409-CONCURRENT /「内容已被他人修改，请刷新后重试」`。
   即：初版写的"需要显式处理乐观锁版本号的搬运"**实际未发生**，被"在应用边界统一翻译异常"替代了。

2. **计数器有两种落地形态，别只认一种。**
   - 即时原子 SQL：`score` / `answerCount` 由 `QuestionRepository.adjustScore / adjustAnswerCount` 发
     `UPDATE qa_question SET ... = ... + ?`，不走整行回写；
   - 缓冲批量累加：`viewCount` 由独立端口 `ViewCounter` 承担（`RedisViewCounter`），请求路径只做一次
     `HINCRBY qa:views:pending`，定时任务（默认 60s）`rename` 摘走当前批次再 `batchUpdate`
     `UPDATE qa_question SET view_count = view_count + ? WHERE id = ?`。
     **它不在 `QuestionRepository` 端口上**——只读该端口的人会误以为浏览数也走整行回写。

3. **约定：聚合内的计数器是只读快照，不得用于需要强一致的判断。**
   `Question` 持有的 `score / answerCount / viewCount` 在并发原子更新后**可能是旧值**（内存对象不会自动刷新）。
   展示一律走读模型 `JdbcQaReadModel`，不要读聚合的计数器。

   已存在一处"聚合内读计数器"的用法需要知情：`Question.softDelete` 里 `answerCount > 0` 拦住
   "已有回答的问题不能由提问者删除"。它读的是 `findById` 时的快照，若此后并发提交了回答，
   存在**窄窗口**：问题被删而回答已落库（回答挂在已删除的问题上，详情页 404、列表也不展示）。
   当前校园场景可接受（窗口毫秒级、无数据损坏），但**若要强一致，得把条件下推到 SQL**——
   `UPDATE qa_question SET deleted_at = ? WHERE id = ? AND answer_count = 0`，用影响行数为 0 回滚并抛
   `QA-1013`，而不是依赖内存里的计数。新增同类判断前先按这条想一遍。

## 被否决的替代方案
- 聚合直接作为 JPA 实体：写起来快，但领域层被框架污染，FF-1 无法成立，也难以讲清六边形架构。
